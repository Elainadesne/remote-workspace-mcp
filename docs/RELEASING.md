# 维护者发布清单

每次发布前审阅下面的检查项。测试通过不等于已经完成真实环境验收，检查表也不代表所有项目都已完成。

## 权利与支持

- [ ] 核实代码、示例和第三方内容可按仓库中的 MIT 许可证发布，并保留必要的版权与许可声明
- [ ] 确认贡献要求、私密漏洞报告渠道、维护范围和支持预期
- [ ] 取得仓库、软件包、制品或部署目标所需的发布授权

## 源码与隐私

- [ ] 审阅源码、文档、测试 fixture、示例、编码字符串及元数据，确保只使用合成或获准发布的数据
- [ ] 检查将公开的 Git 历史、分支、标签、PR、CI 日志及发布附件，排除私人路径、真实会话 ID、凭据和未授权的对话内容
- [ ] 对发现的凭据泄漏先撤销或轮换；仅删除文件不能恢复凭据安全
- [ ] 仅打包需要的源码、合成 examples、配置模板、测试、文档、LICENSE 和 CI；排除 config.json、.env、聊天导入、隧道 profile、日志、.git、__pycache__、*.pyc、虚拟环境和构建中间产物
- [ ] 解开最终 zip/tar 后重新检查内容，核验哈希与文件清单
- [ ] 如使用 setuptools，检查 sdist/wheel 的实际文件列表；不要假定 .gitignore 会控制所有打包工具

## 验证

- [ ] 对最终提交运行完整 unittest 和 compileall；CI 的 Python 3.11/3.12/3.13 均通过
- [ ] 从全新 Linux 源码目录按 README 完成文件-only 配置、拒绝读取边界、stdio 握手和退出流程
- [ ] 在明确授权的目标环境验证当前候选的 Codex 版本兼容、白名单身份检查和分页；其他版本的历史成功不能替代当前候选验收
- [ ] 隧道接入需在操作者确认凭据/权限后验证六个工具的发现与实际调用，并确认停止前台进程会断开连接
- [ ] 记录已知安全边界与未验证环境，不把单元测试视为渗透测试或完整脱敏证明

## 版本与发布

- [ ] 选择版本号，同步 bridge/__init__.py、pyproject.toml、README 和 CHANGELOG
- [ ] 记录通过验证的提交及对应环境；公开候选不得被描述为已经部署的稳定版本
- [ ] 维护者确认正式发布后再创建 tag、release 或软件包；源代码仓库可见不等于已发布这些制品
- [ ] 发布后从实际下载入口核对内容、版本与哈希，并保留可审阅的升级/回退说明
